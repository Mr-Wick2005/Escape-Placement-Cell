PART 1. VISION, GOAL, PURPOSE, DESIGN PILLARS
================================================================================
GAME NAME: Escape: Placement Cell
TAGLINE:   "Three rounds. One door. Zero second chances."

PLAYER GOAL (in-game): Escape the locked Placement Cell building by collecting
three Code Fragments (one per round) and entering the final 3-part door code.

REAL PURPOSE: Make placement preparation fun. The player practices:
  1. Aptitude (logic, quant, verbal, pattern reasoning)
  2. Coding (reading, debugging, writing small functions)
  3. HR interview (structured answers, STAR method, confidence)
and gets an honest, useful performance report at the end.

DESIGN PILLARS (every decision must satisfy these):
  P1. Every round feels like a different ROOM in an escape game, not a quiz.
  P2. Tension without frustration: clear rules, fair hints, no dead ends.
  P3. Learning is hidden inside play, and the final report makes it explicit.
  P4. Looks and sounds premium: dark, neon multicolor, juicy feedback.
  P5. Zero friction: no login, instant start, auto-save, works on mobile.
  P6. Stability over spectacle: no crashes, no soft-locks, no broken states.

TARGET PLAYER: Engineering students (India focus), age 18-24, on phone or
laptop, 15-25 minute session.

TARGET SESSION LENGTH: 18-22 minutes total.
  Hub intro 1 min | Aptitude 6 min | Coding 7 min | Interview 6 min | Finale 2 min

PART 2. STORY AND WORLD
================================================================================
SETTING: "NEXUS Technologies Campus Drive, 11:47 PM." The final day of campus
placements. You are the last candidate. The doors seal. A cold voice speaks:

  THE RECRUITER (an AI that runs the drive, calm, dry humor, slightly
  menacing, secretly fair): "Candidate 404. Every offer letter in this
  building is locked behind three trials. Pass them, and the exit opens.
  Fail them, and you get a very polite rejection email."

THE BUILDING has three sealed wings plus the exit:
  WING A - THE APTITUDE VAULT   (maze of logic doors)       color: CYAN
  WING B - THE CODE CORE        (server room, broken terminals) color: GREEN
  WING C - THE INTERVIEW CHAMBER(dark panel room, one chair)  color: MAGENTA
  THE FINAL GATE                (door that needs all 3 fragments) color: GOLD

MYSTERY LAYER (light story twists, delivered via short text/voice-over):
  - After Round 1 you find a note: "Candidate 403 did not make it past Wing C."
  - After Round 2 the Recruiter slips: "You debug better than the last one."
  - In Round 3 the Recruiter is revealed to be a rejected candidate's
    project that became sentient. Ending choice (see PART 9).

TONE: Dark, witty, motivating. Never insulting, never cruel to the player.
All Recruiter lines must be in /src/content/story.ts (see PART 13), not
hard-coded inside components.

PART 3. PLAYER FLOW AND GAME STRUCTURE
================================================================================
SCREEN FLOW (state machine, see PART 4.1):

  BOOT -> TITLE -> INTRO_CUTSCENE -> HUB
  HUB -> APTITUDE_INTRO -> APTITUDE_PLAY -> APTITUDE_RESULT -> HUB
  HUB -> CODING_INTRO   -> CODING_PLAY   -> CODING_RESULT   -> HUB
  HUB -> INTERVIEW_INTRO-> INTERVIEW_PLAY-> INTERVIEW_RESULT-> HUB
  HUB (all 3 fragments) -> FINAL_GATE -> ENDING -> REPORT -> TITLE

ORDER: Rounds are LINEAR by default (A -> B -> C). Wing B is locked until
Wing A is cleared, Wing C until Wing B is cleared. This keeps the story
coherent. (Future option: free order.)

NO FAIL-STATE DEAD END: If the player fails a round, they get a "Lockdown
Penalty" (time cost + lower rank) but can ALWAYS continue. See PART 4.5.

AUTO START: When the site loads, show TITLE with a single glowing button
"ENTER THE BUILDING". One click starts audio (browsers require a user click
before audio plays) and begins the intro. If a saved game exists, show
"CONTINUE" and "NEW GAME".

PART 4. CORE GAME SYSTEMS
================================================================================
4.1 GLOBAL STATE MACHINE
  Use Zustand store (or XState if preferred) with one source of truth.
  Only ONE screen is active at a time. Every transition is a named action.
  Illegal transitions must be ignored and logged in dev mode.

  state = {
    version: 1,
    screen: 'TITLE' | 'INTRO' | 'HUB' | 'APTITUDE' | 'CODING' |
            'INTERVIEW' | 'FINAL' | 'ENDING' | 'REPORT',
    playerAlias: string,              // optional nickname, default "Candidate 404"
    startedAt: number,
    fragments: { A: string|null, B: string|null, C: string|null },
    rounds: {
      aptitude:  { status, score, maxScore, timeUsed, hintsUsed, attempts },
      coding:    { status, score, maxScore, timeUsed, hintsUsed, attempts },
      interview: { status, score, maxScore, timeUsed, hintsUsed, attempts }
    },
    integrity: number,                // "lives" resource, see 4.4
    totalScore: number,
    settings: { musicVolume, sfxVolume, muted, reducedMotion, voiceEnabled,
                subtitles }
  }
  status: 'LOCKED' | 'AVAILABLE' | 'IN_PROGRESS' | 'CLEARED' | 'FAILED_RETRYABLE'

4.2 SAVE SYSTEM (no login)
  - Autosave to localStorage key "epc_save_v1" after EVERY meaningful action
    (answer submitted, round finished, setting changed).
  - On load: validate with Zod. If invalid or version mismatch, back up the old
    value to "epc_save_backup" and start a fresh save. NEVER crash on bad data.
  - Wrap every localStorage call in try/catch (private mode may block it).
    Fallback: in-memory store.
  - "NEW GAME" requires a confirm dialog.

4.3 SCORING (all numbers live in /src/config/balance.ts, never inline)
  Total = 1000 points max.
    Aptitude  : 300   (30%)
    Coding    : 350   (35%)
    Interview : 300   (30%)
    Style bonus: 50   (speed + no-hint + low-penalty bonus)
  Rank from total:
    900-1000  S  "Offer in Hand"
    750-899   A  "Shortlisted"
    600-749   B  "Waitlisted"
    400-599   C  "Needs Another Drive"
    <400      D  "Back to Practice"
  Clear threshold per round: 60% of that round's points (same as legacy).
  Clear => fragment unlocked. Below 60% => FAILED_RETRYABLE (see 4.5).

4.4 INTEGRITY (the "lives" system)
  - Start with 100 Integrity (shown as a glowing energy bar, "Escape Energy").
  - Wrong answer: -8. Wrong code submission: -10. Weak interview answer: -5.
  - Hint used: -5 each (max 2 hints per puzzle).
  - Integrity regenerates +10 at the start of each new wing (story: "power
    restored").
  - If Integrity hits 0: trigger "LOCKDOWN" (4.5). Never a hard game over.

4.5 LOCKDOWN (fair failure)
  - Screen glitches, red alarm, Recruiter line. Player must wait 10 seconds
    (skippable with a short "breathing" mini-interaction) then Integrity resets
    to 40 and they retry the CURRENT puzzle (not the whole round).
  - Each lockdown subtracts 25 points from Style bonus (floor 0).
  - Round attempts are tracked for the report.

4.6 HINT SYSTEM
  - Every puzzle has 2 hint tiers: Tier 1 nudge, Tier 2 near-answer.
  - Hints cost Integrity AND are logged. Hint text lives in content files.
  - Hint button disabled while a hint cooldown (15 s) runs.

4.7 TIMERS
  - Round timer is VISIBLE, pauses when the tab is hidden (use
    document.visibilityState) and when the settings/pause menu is open.
  - Timer uses performance.now() deltas, not setInterval counting, so it does
    not drift or break in background tabs.
  - Time running out ends the puzzle/round gracefully with partial score.

4.8 CODE FRAGMENTS (the secret codes)
  - Each cleared round awards a fragment shown in the HUD and "Code Wallet":
      Fragment A (Aptitude): 4-digit number     e.g. 7 3 1 9
      Fragment B (Coding):   4-letter word      e.g. B U G S -> derived below
      Fragment C (Interview): 3-symbol sigil    e.g. choose from 6 symbols
  - Fragments are DERIVED from the player's actual play (see each level) so
    they are not static strings in the source. A "master key" check validates
    them at the Final Gate.
  - Wallet is always visible on the HUD, and persists via the save system.

4.9 GLOBAL HUD (visible during every level)
  Top-left: Round name + wing color | Top-center: round timer
  Top-right: Integrity bar, Settings gear | Bottom-left: Code Wallet (A/B/C)
  Bottom-right: Hint button + hints remaining | Mobile: collapses to icons.

PART 6. LEVEL 1: APTITUDE VAULT  (maze + riddles instead of plain MCQ)
================================================================================
CONCEPT: "The Vault Maze." A grid maze (7x7) rendered neon-cyan. The player's
token starts at the entrance and must reach the vault door in the center.
Every junction is guarded by a LOGIC DOOR (an aptitude question). Answer
right: the door opens and the token advances. Answer wrong: lose Integrity and
the door "shifts" (a wall appears, forcing a longer route).

STRUCTURE:
  - 8 question doors total, drawn from a pool of 15+ (randomized per run).
  - Questions are mixed: 3 quantitative, 2 logical/pattern, 2 verbal,
    1 data-interpretation. Categories shown as door glyphs.
  - 1 RIDDLE DOOR (optional bonus): story riddle. Solving gives +20 points
    and a free hint token. Wrong riddle: no penalty (it is a bonus).
  - 1 SECRET PASSAGE: hidden tile found by clicking a flickering wall segment
    (visual clue: the flicker). Reveals a shortcut that skips one question
    (the question is auto-scored as correct at 50% value). This rewards
    observation without breaking scoring.

QUESTION FORMATS (not just radio buttons):
  F1. Classic MCQ rendered as 4 "keypad" buttons.
  F2. Number lock: type a numeric answer on a combination dial.
  F3. Pattern grid: pick the missing tile in a 3x3 shape pattern (SVG).
  F4. Sequence builder: drag tiles into order (use dnd-kit).
  F5. Odd-one-out cards: tap the card that does not belong.
  F6. Cipher: simple Caesar/Vigenere style decode (verbal/logic).
  Mix at least 4 formats per run.

TIMING: 6-minute total vault timer + 45 s per door soft-timer (a door "alarm"
raises tension but only costs Integrity, it never auto-fails).

SCORING (300 pts):
  Per door: 30 pts correct on first try, 15 if correct after one wrong,
  0 if skipped. 8 doors = 240. Riddle bonus up to 20. Speed bonus up to 40.
  Clear threshold: 180.

FRAGMENT A DERIVATION:
  Each correct door reveals one digit glyph in a hidden 4-digit "vault
  combination". Digits = (door answer index values) mapped through a config
  table, so the final number depends on which questions were drawn. The
  vault door asks the player to enter the 4 digits they have seen collected
  (visible in a mini-notebook). Correct => fragment A = those 4 digits.
  IMPORTANT: ALWAYS keep a clear notebook UI so no player has to memorize.

END OF LEVEL: Vault door opens in a satisfying animation, note about
"Candidate 403" is found, results card shows breakdown by category with one
sentence of advice per weak category.

EDGE CASES:
  - Player gets trapped (maze fully blocked): the maze generator must guarantee
    a path exists at every step. Implement path validation (BFS) after every
    wall shift; if blocked, remove the nearest wall.
  - Duplicate questions in a run: forbidden. Shuffle without replacement.
  - Skipping a door: allowed once per level, costs 30 points.

PART 7. LEVEL 2: CODE CORE  (coding round redesigned)
================================================================================
CONCEPT: "Repair the Servers." The room is a dark server hall with 3 broken
terminals. Each terminal is one coding puzzle. Fixing it restores power to a
rack and reveals a letter of Fragment B. Escape condition: restore 3 racks.

THE THREE TERMINALS (difficulty ramps):
  T1 "FIX THE BUG"   - Short function with 1 bug (e.g., off-by-one in a loop,
                       wrong comparison). Player edits and runs tests.
  T2 "FILL THE CORE" - Function skeleton with a missing body. Classic
                       placement question (factorial, palindrome, fizzbuzz
                       variants, max in array, count vowels, two-sum).
  T3 "PREDICT THE LOG" - Show code, player types the exact output (tests code
                       reading). Includes a tricky closure/loop/scope example.
  Choose 1 puzzle per terminal from a pool of 3-4 each, randomized.

EDITOR: Monaco Editor (@monaco-editor/react) with dark custom theme matching
the neon palette. Language selector: JavaScript (default), Python.
(C++/Java/C: keep as READ-ONLY "predict output" snippets only, unless a
safe execution backend is added later. Do NOT claim to run them.)

CODE EXECUTION (safe, no backend required):
  - JavaScript: run inside a Web Worker with a 2-second timeout. Terminate the
    worker if it exceeds the limit (prevents infinite loops freezing the UI).
    Never use eval on the main thread.
  - Python: Pyodide in a Web Worker (lazy-load only when Python is selected,
    show a loading terminal animation). Timeout 3 s via worker termination.
  - Test cases: array of { input, expected } run one by one. Show PASS/FAIL
    lines like a terminal. Hide 1 test as "hidden" to prevent hard-coding.
  - Block dangerous globals in the worker (fetch, importScripts, XMLHttpRequest
    set to undefined) so user code cannot make network calls.

TERMINAL UI: fake CRT screen, scanlines, green text for output, red for
errors. Typing sound on keystroke (very subtle). Run button = "EXECUTE".

SCORING (350 pts):
  Per terminal: 100 pts for all tests passing (+ up to 10 speed bonus).
  Partial: points proportional to tests passed (max 60% if hidden test fails).
  Hints: -10 pts each tier. 3 terminals = 300 + bonus 50 for clean code
  (basic check: no console-log spam, under N lines; keep it simple).
  Clear threshold: 210.

FRAGMENT B DERIVATION:
  Each solved terminal reveals one letter. The 4th "master" letter comes from
  a final one-line "overload" terminal: unscramble the 3 letters into the
  word (config provides 6 possible words: LOOP, BYTE, NODE, HASH, STACK->
  use 4-letter only: LOOP, BYTE, NODE, HASH, CODE, JAVA). Player picks the
  correct word from the scramble. Fragment B = that word.

EDGE CASES:
  - Empty submission: show "No code detected", do not penalize Integrity.
  - Syntax error: show the error line, Integrity -5 only on first error per
    puzzle (never punish typos repeatedly).
  - Worker crash: show "Terminal rebooted", restore the starter code.
  - Pasting a huge input: limit code length to 3000 characters.

PART 8. LEVEL 3: INTERVIEW CHAMBER  (HR round redesigned)
================================================================================
CONCEPT: "The Panel." A dark chamber. A spotlight on one empty chair (you).
Three silhouettes (panel members) with different personalities:
  - THE RECRUITER (HR): behavioral, culture fit
  - THE ARCHITECT (Tech lead): project/skill depth
  - THE SKEPTIC (Senior manager): pressure/curveballs
Each asks questions. The room's light changes with performance: confident
answers brighten the room, weak ones dim it.

STRUCTURE: 7 questions, 1 per "interview card":
  Q1 Warm-up (Tell me about yourself)
  Q2 Strengths/Weakness
  Q3 Project question (Architect)
  Q4 Behavioral STAR (conflict/teamwork)
  Q5 Situational (what would you do if...)
  Q6 Curveball / pressure question (Skeptic)
  Q7 Closing (Why should we hire you / Where do you see yourself)
Questions drawn from per-category pools so replays vary.

INPUT MODES:
  - Type the answer (always available, default fallback).
  - Voice: Web Speech API (SpeechRecognition / webkitSpeechRecognition).
    Feature-detect it. If unsupported (e.g., Firefox), hide the mic and
    show a small note "Voice works on Chrome, Edge, Safari".
    Show live transcript, waveform/pulse visual, and a Stop button.
    Handle errors: not-allowed (mic denied), no-speech, network, aborted.
    Always let the player edit the transcript before submitting.
  - Optional spoken questions: SpeechSynthesis reads questions aloud
    (toggle in settings, default OFF).

ANSWER TIMER: 60 seconds per answer (visible ring). Time up => auto-submit what
exists; empty => 0 points but no lockdown.

SCORING ENGINE (local, deterministic, explainable; no AI needed):
  Score each answer out of ~43 pts (7 x ~43 = 300), using a rubric:
    1. Length/Completeness (0-10): 40-150 words ideal, penalize too short/long.
    2. Relevance keywords (0-12): per-question keyword groups from config.
    3. Structure (0-10): detects STAR markers (situation, task, action, result)
       using simple keyword/phrase patterns; for non-STAR Qs checks
       intro-point-example-conclusion order loosely.
    4. Confidence language (0-5): penalize hedges ("maybe", "I guess", "kind
       of", "I don't know") and filler ("um", "uh", "like" spam).
    5. Specifics (0-6): numbers, named technologies, concrete results.
  Show feedback per answer: 1 strength + 1 improvement tip, plain language.
  Be honest in the report: "This is an automated practice score, not a real
  evaluation."

OPTIONAL AI UPGRADE (later phase, behind a flag): call an LLM through a
BACKEND PROXY ONLY (never put API keys in frontend code) to give richer
feedback. Rate-limit it. The game MUST still fully work without it.

FRAGMENT C DERIVATION:
  The panel "judges" each answer with a sigil. Each good answer (>=60% of its
  points) lights one rune. After 7 answers, the player has up to 7 runes; the
  3 most-lit runes (ties broken by order) form Fragment C. Player must choose
  the correct 3 runes in order on the Final Gate (displayed in the notebook).

THE TWIST: After Q6 the Skeptic says the Recruiter is "not a person". Q7 is
asked by the Recruiter alone, personally. Tone shift: warmer, more human.

EDGE CASES:
  - Mic permission denied: show a friendly modal, continue with typing.
  - Player pastes a giant essay: cap at 1200 chars with live counter.
  - Same answer pasted for all Qs: detect duplicates, score 0 with feedback.
  - Profanity: respond in character, no score, no crash.
  - Speech recognition auto-stops: restart handling, do not lose the text.

PART 9. LEVEL 4: THE FINAL GATE, ENDINGS, REPORT
================================================================================
THE FINAL GATE: A giant gold door with three lock mechanisms:
  Lock 1: 4-digit dial (Fragment A)
  Lock 2: 4-letter word terminal (Fragment B)
  Lock 3: 3-rune slots (Fragment C)
Player enters all three from their Code Wallet notebook. Wrong entry: the
door shakes, -10 Integrity, but NO lockdown at this stage (just a retry).
3 wrong attempts reveals a hint, never a block.

FINAL RIDDLE (last boss moment): The Recruiter asks one reflective riddle
about teamwork/perseverance. Any answer opens the door, but the answer
chosen unlocks one of 3 ENDINGS' dialogue variants (flavor only).

ENDINGS (based on total score rank):
  S: "Offer in Hand" - confetti, golden light, the Recruiter salutes.
  A: "Shortlisted" - the door opens, a warm email notification.
  B: "Waitlisted" - the door opens slowly, "Keep practicing" tone.
  C/D: "Back to Practice" - the door opens anyway (never trap the player),
       the Recruiter gives a pep talk and a recommended study list.
All endings finish in the REPORT.

PERFORMANCE REPORT (printable, shareable):
  - Overall score, rank, animated rank reveal.
  - Round-by-round breakdown with charts (recharts or custom SVG).
  - Skills radar chart: Quant, Logic, Verbal, Debugging, Coding, Communication,
    Confidence.
  - Top 3 strengths, top 3 improvements (generated from round data).
  - Personalized action plan (3-5 bullets) with free resource categories
    (not fake links; categories only, e.g. "Practice recursion basics").
  - Buttons: Play Again, Download Report (html-to-image -> PNG, optional PDF
    via print stylesheet), Share Score (Web Share API with fallback copy).
  - Honest disclaimer line about automated scoring.

PART 12. MOTION AND EFFECTS DESIGN
================================================================================
LIBRARIES: Framer Motion (UI/transitions), GSAP (timelines, hero sequences),
canvas-confetti (celebrations), tsparticles or custom canvas (ambient dust).

MOTION RULES:
  - Screen transitions: 400-600 ms, cross-fade + slight scale/blur.
  - Micro-interactions: 120-200 ms. Spring physics for doors/tokens.
  - Door open: split panels slide apart with light bleed through the gap.
  - Correct answer: green pulse + particles burst; wrong: shake + red flash.
  - Glitch effect (CSS clip-path + RGB split) for lockdown and Recruiter
    reveals; max 600 ms per burst.
  - Text effects: typewriter for story lines (skippable by click), scramble-
    decode effect for fragment reveals.
  - Timer < 10 s: pulsing red + tick SFX.

16.1 UNIT TESTS (Vitest) - must exist for:

  - maze.ts (path always exists across 1000 seeds, after every wall shift)
  - derivations.ts (fragments deterministic for given inputs)

  - persist.ts (corrupt JSON, wrong version, missing fields, storage blocked)
  - content validation: every question has valid answer, hints, unique id.

16.2 COMPONENT TESTS: HUD, Integrity bar, Wallet, Hint button states,
  Terminal output, Door states.

16.3 E2E TESTS (Playwright, desktop + mobile viewport):
  - Full playthrough happy path (S rank) using seeded RNG for determinism.
  - Failing a round then retrying; Lockdown flow; reload mid-round resumes.
  - Mic denied path; unsupported speech path (mock).
  - Infinite loop in coding terminal is terminated.
  - Settings: mute, reduced motion persist across reload.

16.4 KNOWN BUG TRAPS TO PREVENT
  - Audio before user gesture -> start only after click.
  - Timers running in hidden tabs -> pause on visibilitychange.
  - Memory leaks -> dispose Three.js geometries/materials, stop workers,
    unload Howler sounds, remove listeners on unmount.
  - Double-submits -> disable buttons while processing; guard in store actions.
  - Race conditions on screen transitions -> single transition lock.
  - Stale closures in timers -> use refs or store selectors.
  - Hydration of old saves -> versioned schema + migration function.
  - Soft-locks -> every state must have a visible, working way forward
    (verify by test: from every screen, a valid action exists).
  - Mobile keyboard covering inputs -> scroll into view, use dvh units.
  - Pyodide big download -> show progress, cache, allow JS-only fallback.
  - Random content repeating -> seeded shuffle without replacement.

16.5 DEFINITION OF DONE (global)
  [ ] Zero TypeScript errors, zero ESLint errors
  [ ] All unit + E2E tests green
  [ ] No console errors/warnings in a full playthrough
  [ ] Lighthouse: Performance >= 90, Accessibility >= 95, Best Practices >= 95
  [ ] Works Chrome, Edge, Safari, Firefox (voice degrades gracefully)
  [ ] Works at 360px mobile width and 1920px desktop
  [ ] Game completable by keyboard only
  [ ] Reload at any point restores the correct state
